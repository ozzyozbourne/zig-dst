Coverage marks & exhaustive testing

A sweep that passes proves nothing about code it never reached. Here a free-space map (an extent set that coalesces and splits ranges in a fixed-size array) has a planted bug on one rare path. A million random seeds pass. The coverage marks show why: that path was hit zero times. An exhaustive generator in the style of TigerBeetle's exhaustigen.zig walks every op sequence on a 7-block domain and prints the 4-op counterexample in 8 ms.

01The system, its marks, and two ways to feed it

The system under test is IntervalSet: sorted, disjoint, non-touching ranges [lo, hi) of free blocks, stored in a fixed array of slots, like a B-tree node. insert and remove must open slots, close slots (in-place compaction), coalesce neighbours and split ranges. Each of those branches carries a named coverage mark. The same harness can be fed by a seeded random generator, or by Gen, which enumerates every choice sequence. After every op the harness checks the set's shape and compares its contents with an independent bitset model.

The bug: one line of a fast path

main.zig · IntervalSet.insert, correct (close_slots: ordered remove)
if (touching == 2 and set.slots[i].hi == lo and set.slots[i + 1].lo == hi) {
    marks.hit(.insert_fill_gap);
    set.slots[i + 1].lo = set.slots[i].lo;
    set.close_slots(i, 1);
    return;
}
fn close_slots(set: *IntervalSet, at: u32, count: u32) void {
    std.mem.copyForwards(Interval, set.slots[at .. set.len - count], set.slots[at + count .. set.len]);
    set.len -= count;
}
main.zig · with --bug-fill-gap (swap-remove)
if (touching == 2 and set.slots[i].hi == lo and set.slots[i + 1].lo == hi) {
    marks.hit(.insert_fill_gap);
    set.slots[i + 1].lo = set.slots[i].lo;
    // BUG: swap-remove is O(1) and looks harmless, but it moves the LAST interval
    // into slot i. That is right only when slot i+1 was the last one (then the last
    // one IS the fused range). With anything after it, the array is now unsorted.
    set.slots[i] = set.slots[set.len - 1];
    set.len -= 1;
    return;
}

Why a random generator never gets here: the fast path needs lo to equal the left neighbour's hi and the length to equal the hole, exactly, on a domain of 220 blocks. Two exact equalities on a big domain is a measure-zero event. On a domain of 7 blocks it is one of 36 possible ops.

04Exhaustive enumeration: Gen, the odometer

Gen replaces the PRNG. Each pass of while (!g.done()) asks for choices with bounds (kind ≤ 1, lo ≤ 6, hi - lo - 1 ≤ min(3, 7 - lo) - 1). done() bumps the rightmost choice still below its bound and forgets everything after it. Because hi's bound depends on lo, the space is a tree, not a grid; Gen still visits every leaf exactly once. Below: the tree of one op (36 leaves), and the odometer stepping through it.

src/testing/marks.zig · record

//! That is, the important part is not that a log line is covered at all, but that we
//! can trace production code to a single minimal hand-written test which explains why
//! the code needs to exist.
fn record(fmt: []const u8) void {
    comptime assert(builtin.is_test);
    if (global_state.mark_name) |mark_active| {
        if (std.mem.indexOf(u8, fmt, mark_active) != null) {
            global_state.mark_hit_count += 1;
        }
    }
}

This example's marks module has the same check / expect_hit shape, but its counters are always on, so the simulator can print the coverage table. Its zig test for insert_fill_gap is the 4-op sequence from section 03.

src/testing/exhaustigen.zig · done

pub fn done(g: *@This()) bool {
    if (!g.started) {
        g.started = true;
        return false;
    }
    var i = g.p_max;
    while (i > 0) {
        i -= 1;
        if (g.v[i].value < g.v[i].bound) {
            g.v[i].value += 1;
            g.p_max = i + 1;
            g.p = 0;
            return false;
        }
    }
    return true;
}

main.zig's Gen is a line-for-line port (std only). Sequences come out shortest first, so the first failure is a minimal one, as matklad's Generate All the Things notes.

09Run it yourself

$ cd examples/12-coverage-marks-exhaustive
$ zig run main.zig -- sweep 100000 --bug-fill-gap                 # passes: the bug is never reached
$ zig run main.zig -- coverage 100000 --bug-fill-gap --require-all  # insert_fill_gap = 0: fails
$ zig run main.zig -- exhaust 4 --bug-fill-gap                     # minimal 4-op counterexample
$ zig run main.zig -- sweep 100000 --gen-boundaries --bug-fill-gap # a better generator finds it too
$ zig run main.zig -- run 1 --gen-boundaries --bug-fill-gap
$ zig test main.zig                                               # each test asserts one mark
