EasyExample 01std.Random · Wyhash

The seed is everything

The smallest possible deterministic simulation. One u64 seed feeds one PRNG, and that PRNG is the only source of randomness in the test. When the test fails, the printed seed is a complete bug report: replay it and you get the same inputs, the same failure and the same trace hash. The system under test is a tiny function, average(a, b) on u32, whose buggy version overflows. Everything below comes from real runs of examples/01-seeded-randomness/main.zig (Zig 0.17, ReleaseSafe).

02The biased generator: generate the inputs that matter

fn gen_value(random: std.Random) u32 {
    return switch (random.uintLessThan(u8, 100)) {
        0...97 => random.uintAtMost(u32, 1_000_000), // typical
        98 => random.int(u32), // anywhere
        else => std.math.maxInt(u32) - random.uintAtMost(u32, 16), // edge
    };
}

Every value costs two PRNG draws: a roll in 0..99 that picks a bucket, then the value itself. Real bugs live at the edges, so 1% of values sit within 16 of maxInt(u32). A uniform generator puts nearly all of its mass in the "anywhere" range and almost never hits an exact edge.

03Where the inputs land: the overflow region

(a +% b) / 2 is wrong exactly when a + b > 2³² − 1, the shaded triangle. Each dot is one real (a, b) pair from the first 400 seeds (sweep 400 --dump). The left plot uses the shipped biased generator. The right plot uses the opt-in --uniform flag (exercise 1 in NOTES.md). Switch to log axes to see the three buckets separate.

So why not use uniform inputs? A uniform generator would find this bug instantly, but it hides the lesson. Most real bugs are not "half of all inputs are wrong". They sit on narrow edges such as maxInt, zero, or a boundary ±1, and uniform sampling almost never lands on those. Hand-written tests stay in the bottom-left corner (average(2, 4)) and never reach the triangle. The biased generator reaches it on purpose, at a controlled rate.

05The bug, bit by bit

Buggy (--bug)

fn average(a: u32, b: u32) u32 {
    if (bug_enabled) {
        // Wrapping add so the bug shows up as a wrong
        // answer instead of a Zig safety panic.
        return (a +% b) / 2;
    }
    ...

Correct

fn average(a: u32, b: u32) u32 {
    ...
    // Correct: never overflows.
    return a / 2 + b / 2 + (a & b & 1);
}

// Oracle in run_seed(): a wider type cannot overflow.
const want: u32 = @intCast((@as(u64, a) + @as(u64, b)) / 2);

These are the inputs of the failing step of seed 0, parsed from the captured log. A 32-bit adder produces 33 bits of result. +% keeps the low 32 and silently drops the carry out of bit 31, which is worth 2³² = 4,294,967,296. Halving the wrapped sum gives a value that is too small by exactly 2³¹.

var prng = stdx.PRNG.from_seed(seed);

    options_lite(&prng)
else if (cli_args.performance)
    options_performance(&prng)
else

The same pattern at full scale. Either the seed is given, or one fresh random seed is drawn. It is logged first (SEED={}), and every cluster option and sub-seed is then derived from that single PRNG. When the run fails, it logs you can reproduce this failure with seed={} (line 349).

src/testing/fuzz.zig · biased distributions

/// Returns an integer of type `T` with an exponential distribution of rate `avg`.
pub fn random_int_exponential(prng: *stdx.PRNG, comptime T: type, avg: T) T {
    ...
    const random = std.Random.init(prng, stdx.PRNG.fill);
    const exp = random.floatExp(f64) * @as(f64, @floatFromInt(avg));
    return std.math.lossyCast(T, exp);
}

TigerBeetle's fuzzers do not draw uniformly either. Sizes and counts are mostly small and occasionally huge (exponential). range_inclusive_ms (line 71) draws durations, and the swarm-testing helpers turn whole features off for some seeds. All of these exist so that seeds keep reaching the rare edges.

09Run it yourself

$ cd examples/01-seeded-randomness
$ zig run main.zig -- sweep 10000            # correct code: every seed passes
$ zig run main.zig -- sweep 10000 --bug      # stops at the first failing seed and prints the replay command
$ zig run main.zig -- run 0 --bug            # the replay: same inputs, same trace hash, every time
$ zig run main.zig -- run 0 --bug --dump     # opt-in: print every step's bucket rolls and (a, b)
$ zig run main.zig -- sweep 10000 --bug --uniform  # opt-in: uniform u32 inputs (exercise 1)
