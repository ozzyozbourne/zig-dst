Clock skew & leases

Example 02 had one clock. Here each of 3 nodes has its own: an oscillator that drifts by a seeded amount within ±2000 ppm, and a wall clock that NTP can step. The leader serves reads from a lease measured on its own clock. Followers promise on their own clocks not to elect anyone else until the lease is over. Only the simulator knows true time. On every tick it checks that at most one node holds a lease and that every lease read returns the latest committed write. Below are the real runs where the clocks disagree enough to break both.

01One true time, three local clocks

The simulator advances true time, one tick = 1 ms. Each node only sees what its Clock reports. monotonic runs at 1 + drift_ppm/10⁶ of true speed. realtime is monotonic plus an offset that starts at ±50 ms and moves with every NTP-style step. 03The margin: why 2·ρ·lease

The leader stamps a heartbeat with its clock reading s. The follower promises lease on its own clock, starting when the heartbeat arrives, which is later in true time than s. In the worst case the leader's clock is slow by ρ and the follower's is fast by ρ. Then the leader's lease lasts (lease − m)/(1−ρ) in true time and the promise lease/(1+ρ). Safety needs the first to be no longer than the second.

Node.leader_lease_us with --bug-no-drift-margin

fn leader_lease_us() i64 {
    // THE BUG: trust that the leader's clock and the followers' clocks tick at the same rate.
    if (bug_no_drift_margin) return lease_us;
    return lease_us - drift_margin_us - margin_guard_us;
}

The constants it should use

const drift_bound_ppm: i64 = 2000;
const lease_us: i64 = 5000 * us_per_ms;
const drift_margin_us: i64 = 2 * drift_bound_ppm * lease_us / 1_000_000;
/// Plus a guard for clock-read granularity (clocks are read once per tick).
const margin_guard_us: i64 = 2 * us_per_ms;

04The wall-clock bug: a step backwards stretches the lease

Node.lease_clock picks the clock that every lease deadline and promise deadline is measured with. Realtime "is the time", and most of the time it advances like monotonic, so every test without a clock step passes. In the isolated leader's realtime clock steps by . The lease deadline did not move, but the clock it is compared with did, so the lease lasts that much longer in true time.

Node.lease_clock

/// THE CLOCK CHOICE. Durations must be measured with the monotonic clock: realtime is for
/// telling the time, and it jumps whenever NTP or an operator steps it.
fn lease_clock(node: *const Node) i64 {
    if (bug_wall_clock) return node.real; // THE BUG: a step moves every lease deadline
    return @intCast(node.mono);
}

05Across many seeds: drift vs overlap

The capture script replays seeds 0–599 in each mode. For each run it records the tightest handover after a lease ran out: the true ticks from the end of the old leader's lease to the start of the new leader's lease. The value is negative when the two leases overlap. Handovers where the old leader stepped down on seeing a higher term are left out, because they do not depend on drift. The x axis is how much faster the new leader's clock runs than the old leader's. Without the margin, the points fall along the drift line, and every seed to the right of where the line crosses zero is at risk. With the margin, the whole line shifts up by 22 ms and every point stays above zero. The wall-clock bug's overlaps do not follow drift at all, because the steps cause them.

07How TigerBeetle does this

src/stdx/time.zig · Time

/// A timestamp to measure elapsed time, meaningful only on the same system, not across reboots.
/// Always use a monotonic timestamp if the goal is to measure elapsed time.
/// This clock is not affected by discontinuous jumps in the system time, for example if the
/// system administrator manually changes the clock.
pub fn monotonic(self: Time) Instant { ... }

/// A timestamp to measure real (i.e. wall clock) time, meaningful across systems, and reboots.
/// This clock is affected by discontinuous jumps in the system time.
pub fn realtime(self: Time) InstantUnix { ... }

--bug-wall-clock is the mistake this comment warns about. TimeOS.monotonic uses CLOCK_BOOTTIME on Linux and panics with "a hardware/kernel bug regressed the monotonic clock" if it ever goes back. Node.read_clock asserts the same.

src/stdx/time.zig · TimeSim.offset

switch (self.offset_type) {
    .linear => {
        const drift_per_tick = self.offset_coefficient_A;
        return @as(i64, @intCast(ticks)) * drift_per_tick + ...offset_coefficient_B...;
    },
    .periodic => { ... std.math.sin(... * 2 * std.math.pi / ...B) ... },
    .step => {
        return if (ticks > self.offset_coefficient_B) self.offset_coefficient_A else 0;
    },
    .non_ideal => { ... floatNorm(f64) * 10 ... + offset_random },
}

The VOPR's simulated clock: linear drift, a periodic wobble, a step, or a noisy mix. TimeSim.tick keeps monotonic ideal and applies the offset to realtime only. This example puts the linear model in the oscillator, so monotonic drifts too, which a lease must survive. It applies the step model to realtime.

src/vsr/clock.zig · the header and Clock.realtime_synchronized

//! Time plays a central role in TigerBeetle data model. Because it is so important, TigerBeetle
//! defines its own time. In other words, we don't use time to drive consensus, we use consensus to
//! drive time!
...
return std.math.clamp(
    self.realtime(),
    self.epoch.realtime + elapsed + interval.lower_bound,
    self.epoch.realtime + elapsed + interval.upper_bound,
);

Replicas ping and pong. Clock.learn(replica, m0, t1, m2) measures the round trip with monotonic and the remote clock with realtime. synchronize runs Marzullo's algorithm (src/vsr/marzullo.zig) for the smallest interval that a quorum agrees on, starting from clock_offset_tolerance_max (10 s in src/config.zig). The epoch measures elapsed with monotonic, and expires after clock_epoch_max because "Gradual clock drift prevents us from using an epoch for more than a few seconds".

src/vsr/replica.zig · on_request

const realtime: i64 = if (message.header.client == 0)
    @intCast(message.header.timestamp)
else
    self.clock.realtime_synchronized() orelse {
        if (!self.primary_abdicate_timeout.ticking) {
            assert(!self.solo());
            self.primary_abdicate_timeout.start();
        }
        log.warn("{f}: on_request: dropping (clock not synchronized)", ...);
        return;
    };

A primary that cannot agree on the time with a quorum stops timestamping and eventually abdicates. TigerBeetle has no leases. Its timeouts (vsr.Timeout in src/vsr.zig) count local ticks, and correctness never depends on two replicas' clocks agreeing. This example shows what a design that does depend on that has to get right.
