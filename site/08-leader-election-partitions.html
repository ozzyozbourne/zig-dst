Leader election & partitions

A Raft-style election (terms, votedFor, heartbeats, randomized timeouts) among 3–5 nodes. The simulator partitions the network the way TigerBeetle's PacketSimulator does, including asymmetric partitions, and crashes nodes so that only their simulated disk survives. On every tick a checker asserts at most one leader per term, ever. Below are the real replays that break it, two leaders in one term, drawn tick by tick.

How to read the views

Messages in the cluster views are implied by the logged event: ? broadcasts RequestVote, v sends a vote to the candidate, and * sends heartbeats. They are drawn only on links the partition matrix allows. The log does not print individual packets.

Matrix cell [from][to] is green when packets from from reach to. In an asymmetric partition such as 1>0234 the matrix is not symmetric: row 1 is green, column 1 is red.

03What survives a crash: disk vs memory

A crash runs node.* = .{ .id, .up = false, .disk = node.disk, .prng = node.prng }: every volatile field is reset, and only Disk and the node's PRNG ("its hardware") survive. restart reloads the term and vote from disk. The rule is to persist before replying. --bug-volatile-vote breaks it for exactly one field.

Node.persist, as in main.zig

fn persist(node: *Node) void {
    node.disk.current_term = node.current_term;
    // THE BUG: votedFor never reaches the disk, so a restart forgets who we voted for.
    node.disk.voted_for = if (bug_volatile_vote) none else node.voted_for;
}

Why tests without crashes never see itWithout a crash, the in-memory voted_for is still right, so every crash-free test passes. The failure needs a vote in term t, then a crash before the term moves on, then a second candidate asking in the same term t, and that vote has to decide the majority.

04Replay: run 0 --bug-no-quorum and the asymmetric partition

With this bug, votes_needed counts only the peers heard from in the last 100 ticks. In net:1>0234, node 1 can send to everyone but receives nothing. After 100 ticks it believes it is a cluster of one, and its own vote is a "majority".

votes_needed with --bug-no-quorum

fn votes_needed(sim: *const Simulator, node: *const Node) u8 {
    if (!bug_no_quorum) return sim.quorum(); // a majority of ALL nodes, reachable or not
    var reachable: u8 = 1;
    for (0..sim.n()) |peer| {
        if (peer == node.id) continue;
        if (node.last_heard[peer] + reachable_window >= sim.tick) reachable += 1;
    }
    return reachable / 2 + 1;
}

08How TigerBeetle does this

src/testing/packet_simulator.zig · auto_partition_network

const enabled =
    from >= self.options.node_count or
    to >= self.options.node_count or
    partition[from] == partition[to] or
    (self.options.partition_symmetry == .asymmetric and
        partition[from] == asymmetric_partition_side);

PartitionMode (none, uniform_size, uniform_partition, isolate_single), PartitionSymmetry and the stability counters. Simulator.partition_network in this example uses the same link rule. src/vopr.zig picks the mode and symmetry per seed.

src/vsr/replica.zig · view_durable

/// The highest durable view.
/// A replica must not advertise a view higher than its durable view.
///
/// The advertised `view` must never backtrack after a crash.
/// This ensures the old primary is isolated — if a backup's view backtracks, it could
/// ack a prepare to the old primary, forking the log. See VRR §8.2 for more detail.

TigerBeetle's view is the counterpart of Raft's term. view_durable_update() persists through SuperBlock.view_change. --bug-volatile-vote is a small version of the bug this comment warns about.

src/vsr.zig · quorums(replica_count)

assert(quorum_view_change >= @divFloor(replica_count, 2) + 1);
assert(quorum_view_change + quorum_replication > replica_count);

Quorums depend on the configured replica count, never on how many replicas are reachable. --bug-no-quorum breaks exactly this rule.

src/testing/cluster.zig · replica_crash

// Reset the storage before the replica so that pending writes can (partially) finish.
cluster.storages[replica_index].reset();

cluster.replicas[replica_index].deinit(cluster.allocator);
cluster.network.process_disable(.{ .replica = replica_index });

Storage outlives the replica object. replica_restart reopens the replica from that storage, just as Simulator.restart reloads from Disk here. The VOPR's liveness mode (transition_to_liveness_mode in src/vopr.zig) corresponds to enter_liveness_mode.
