Storage fault atlas

Disks flip bits on write, flip bits on read, rot while idle, and sometimes write a perfectly good block to the wrong address. This example keeps a 3-replica block log alive through all of that with checksums, verified reads, repair from a peer, a background scrubber and a storage checker. The key trick is that the simulator decides before the run where each replica may fail (the fault atlas), so every block always has one good copy. Every failure it reports is then a real bug, never bad luck.

01The system under test and the simulated disk

Three replicas each own a disk of 32 × 64-byte blocks. In the simulation a disk is just a byte array, disks[replica][block], so a flipped bit really changes the bytes that the verification code sees. Everything in green below is the real logic under test; everything in amber is the simulated world around it. One seed drives all of it.

One tick of simulate()

1. Workload: with 15% chance append the next block (until 32), otherwise a client reads a random block from a random replica.
2. Bit rot: with rot_pct chance flip a bit of data at rest.
3. Every 3 ticks the scrubber verifies one (replica, block).
4. Every 100 ticks a checkpoint: faults pause, every replica scrubs its whole log, then the storage checker requires byte-identical logs.
5. check_atlas(): the harness itself must still hold a good copy of every block.

Four invariants, checked while it runs

CorruptDataReturned a client read returned bytes that differ from the oracle expected[].
StorageMismatch after the checkpoint repair sweep the replicas' logs differ.
Unrepairable a repair found no valid copy on any peer (liveness).
panic check_atlas: the test harness broke its own promise. It panics instead of blaming the system.

02The fault atlas: where each replica is allowed to fail

Before the first tick, FaultAtlas.init walks the 32 blocks and, for each one, marks faults_max = replica_count − 1 = 2 distinct replicas as faulty for that block. All four kinds of fault (write flip, read flip, rot, and both ends of a misdirected write) are only injected in faulty cells. Below is the real atlas of seed 1 (parsed from the program's output). Why the rule existsLet the injector corrupt all three copies of a block and the data is gone. No replicated system can recover from that, so the test "fails" while the code is correct. That is a false alarm, and after a few of them nobody trusts the simulator. The NOTES exercise that makes eligible() ignore the atlas gets exactly that: the check_atlas panic at seed 0 and Unrepairable at seed 1, with no bug flag set.

03Block layout: what the checksum must cover

A block is [checksum: u64][payload: 56 bytes]. Its address is not stored in the block. It is implied by its position on disk. So if the checksum covers only the payload, a whole valid block written to the wrong slot still verifies. The correct checksum is Wyhash(address ‖ payload), which binds the bytes to their slot.

The real code (main.zig)

fn checksum(address: u64, payload: *const Payload) u64 {
    var h = std.hash.Wyhash.init(0);
    if (!bug_misdirect) h.update(std.mem.asBytes(&address));
    h.update(payload);
    return h.final();
}

fn block_valid(address: u64, block: *const Block) bool {
    const stored = std.mem.readInt(u64, block[0..checksum_size], .little);
    return stored == checksum(address, block[checksum_size..]);
}

Line 3 is the whole --bug-misdirect difference: with the flag set, the address is never hashed.

The other planted bug: the local read path

fn client_read(sim: *Sim, replica: u8, address: u32) Failure!void {
    var block = sim.disk_read(replica, address);
    if (!bug_trust_read and !block_valid(address, &block)) {
        block = try sim.repair(replica, address);
    }
    const payload = block[checksum_size..];
    sim.event(.client_read, replica, address, std.hash.Wyhash.hash(0, payload));
    // Invariant 1 (safety), checked on every single read, not at the end.
    if (!std.mem.eql(u8, payload, &sim.expected[address])) {
        return sim.fail(error.CorruptDataReturned, replica, address);
    }
}

With --bug-trust-read the condition on line 3 is always false: "the disk said OK". repair() and the scrubber still verify, so a review that greps for checksum checks finds them.

08How TigerBeetle does it

This example is a small copy of the storage fault model in TigerBeetle's simulator. The snippets below are quoted from the checkout at /home/user/workspace/tigerbeetle (commit 0450c32b2).

src/testing/storage.zig · ClusterFaultAtlas.init

const faults_max = quorums.replication - 1;
assert(faults_max < replica_count);
...
for (0..chunks[0].bit_length) |chunk| {
    var replicas: ReplicaSet = .{};
    while (replicas.count() < faults_max) {
        const replica_index = prng.int_inclusive(u8, replica_count - 1);
        if (chunks[replica_index].count() + 1 <
            chunks[replica_index].capacity())
        {
            chunks[replica_index].set(chunk);
            replicas.set(replica_index);
        } else {
            // Never corrupt all chunks of a particular replica.
            // (For the WAL, this can cause error.WALInvalid).
        }
    }
}

Chunks are WAL header sectors, client-reply slots and grid blocks. TigerBeetle's bound is quorums.replication − 1 (a block must be valid at a majority for VSR recovery). Ours is replica_count − 1.

src/testing/storage.zig · header comment

//! Storage injects faults that a fully-connected cluster can
//! (i.e. should be able to) recover from.
//! ...
//! - wal_headers, wal_prepares:
//!   - Read/write faults are distributed between replicas according
//!     to ClusterFaultAtlas, to ensure that at least one replica will
//!     have a valid copy to help others repair.
//! - grid:
//!   - Similarly to prepares and headers, ClusterFaultAtlas ensures
//!     that at least one replica will have a block.
//!   - When replica_count≤2, grid faults are disabled.

src/testing/storage.zig · Storage.overlays (misdirects)

/// Each misdirected write creates two overlays.
/// - The intended target is overlaid with its old data.
/// - The mistaken target is overlaid with the `write.buffer` data.
/// ...
///   - misdirections are always within the same zone,
///   - the entire write is misdirected (rather than only some of
///     the sectors), and
///   - the misdirected write lands on a convenient offset.
///   ... The goal here is to test how TigerBeetle handles
///   well-formed but incorrectly-located data.

write_sectors_finish_overlay_misdirect picks the wrong target with pick_faulty_chunk_offset, i.e. only among the same replica's faulty chunks. Our misdirect_target does the same.

src/vsr/grid.zig · read_block_validate

fn read_block_validate(block: BlockPtrConst, expect: struct {
    address: u64,
    checksum: u128,
}) ReadBlockResult {
    if (!header.valid_checksum()) return .invalid_checksum;
    ...
    if (header.checksum != expect.checksum) return .unexpected_checksum;
    ...
    assert(header.address == expect.address);
    return .{ .valid = block };
}

Grid block headers store address and the header checksum covers it. The reader also knows the checksum it expects (from the parent reference), so a misdirected or stale block cannot pass.

src/testing/cluster/storage_checker.zig · checksum_grid

const block_header = schema.header_from_block(block);
assert(block_header.address == block_address);

stream.add(block[0..block_header.size]);
// Extra guard against identical blocks:
stream.add(std.mem.asBytes(&block_address));

check() stores the first replica's checksums per op_checkpoint and returns error.StorageMismatch when a later replica differs. Our checkpoint hash mixes in the address the same way.

src/testing/storage.zig · transition_to_liveness_mode

pub fn transition_to_liveness_mode(storage: *Storage) void {
    ...
    storage.options.read_fault_probability = Ratio.zero();
    storage.options.write_fault_probability = Ratio.zero();
    storage.options.write_misdirect_probability = Ratio.zero();
    storage.options.crash_fault_probability = Ratio.zero();
}

Our final phase does the same (faults_enabled = false), then repairs everything and reads every block from every replica. The scrubber is a tiny version of src/vsr/grid_scrubber.zig, which reads the grid in the background "to discover faults proactively".
